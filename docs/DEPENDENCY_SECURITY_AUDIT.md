# Dependency security audit

Audit date: **2026-10-05 (Asia/Shanghai)**. Reviewed product baseline: `ee0389464bb332e3e86443d2e3a7cceaa2f1b837`. Scope: the frontend and Node API npm trees, their existing runtime usage, and the existing release gates. No product feature or service architecture change is required by the triage.

## Baseline and measurement

The successful baseline installs, lint, tests and frontend production build passed before dependency changes: frontend **28/28 tests in eight files** and API **14/14 tests, zero skips**. Audits were run separately with and without development dependencies. npm counts affected package records, including transitive and aggregate records; the counts are not numbers of distinct advisories or remotely exploitable production defects.

| Measurement | Frontend full | Frontend production only | API full | API production only |
| --- | --- | --- | --- | --- |
| Previously reviewed CI signal | 20 (2 low, 6 moderate, 12 high) | Not recorded in that signal | 2 high | Not recorded in that signal |
| Successful fresh baseline | 20 (2 low, 6 moderate, 12 high) | 3 high | 2 high | 1 high |
| After dependency updates | 0 | 0 | 0 | 0 |

The production baseline consists of frontend `react-router-dom`, `react-router`, and `turbo-stream`, and API `jws`. There is **no `mongodb-memory-server` advisory** in the successful API baseline. An early network-incomplete scan produced frontend 36/API 8 package records with missing aggregate ranges and misleading `fixAvailable: false`; it was discarded after registry/proxy recovery and is not the release baseline or evidence of an absent upstream fix.

Exact package manifests, lockfiles and successful audit JSON were captured before updates; command logs and after-update audits are separate evidence artifacts. This document summarizes them instead of embedding audit JSON. Severity and affected ranges in the advisory inventory are the actual concrete `via` objects, not the maximum severity propagated through a parent package.
